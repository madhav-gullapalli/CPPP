CP++ Error Documentation
========================

This file documents the native CP++ diagnostics currently produced before
falling back to generated C++ compiler errors.

Diagnostics begin with a short headline, followed by a `--> file:line:column`
location and a numbered source frame. The first `^` marks the beginning of the
primary span and following `~` characters cover the rest of the affected token
or expression. Labels explain the highlighted code, while notes and potential
fixes appear below the frame as `= note:` and `= help:`.

General syntax
--------------

missing semicolon
  A CP++ statement must end with a semicolon.

  Example:
    print("hello")

  Diagnostic:
    error: missing semicolon
     --> example.cppp:1:15
      |
    1 | print("hello")
      |               ^ statement ends here
      |
      = help: add `;` to terminate the statement

missing semicolon after a bare call
  A balanced call on one line is a complete statement candidate. If its
  semicolon is missing, CP++ diagnoses that line instead of merging the call
  with the next statement.

  Example:
    moveDisks()
    print(1);

  Diagnostic:
    error: missing semicolon
     --> example.cppp:1:12
      |
    1 | moveDisks()
      |            ^ statement ends here
      |
      = help: add `;` to terminate the statement

unsupported statement
  The statement is not recognized by the current compiler frontend. When its
  leading name is close to a statement or callable that is valid in this
  context, CP++ suggests the nearest unambiguous spelling.

  Example:
    pritn(1);

  Diagnostic:
    error: unsupported statement
     --> example.cppp:1:1
      |
    1 | pritn(1);
      | ^~~~~
      |
      = help: did you mean 'print'?

assignment used instead of comparison
  Assignment is not an expression in CP++. Use == when a condition needs to
  compare two values.

  Example:
    int n = 1;
    if (n = 0) {
    }

  Diagnostic:
    error: unexpected token in expression
     --> example.cppp:2:7
      |
    2 | if (n = 0) {
      |       ^
      |
      = help: use `==` to compare values

Primitive type errors
---------------------

primitive type tree
  CP++ stores types internally as a primitive root with a list of subtype
  children. The current user-facing roots are int, float, char, bool,
  string, and List<T>. The primitive roots int, float, char, bool, and
  string each expect zero subtypes, while List expects exactly one subtype.

  Example:
    int x;
    float y;
    char c;
    bool ok;
    string name;
    List<int> values;
    List<List<char>> table;

expected variable name after <type>
  A primitive declaration must provide a valid identifier after the type.

  Example:
    int = 5;

  Diagnostic:
    error: expected variable name after int
     --> example.cppp:1:5
      |
    1 | int = 5;
      |     ^

variable '<name>' is already declared
  A variable name cannot be declared twice in the same current scope.

  Example:
    int x;
    int x;

  Diagnostic:
    error: variable 'x' is already declared
     --> example.cppp:2:5
      |
    2 | int x;
      |     ^

expected value after '='
  A declaration assignment has an equals sign but no value.

  Example:
    int x =;

  Diagnostic:
    error: expected value after '='
     --> example.cppp:1:8
      |
    1 | int x =;
      |        ^

expected ';' or '=' after variable name
  Extra tokens appeared after a variable name in a declaration.

  Example:
    int x y;

  Diagnostic:
    error: expected ';' or '=' after variable name
     --> example.cppp:1:7
      |
    1 | int x y;
      |       ^

expected variable name after ','
  A comma-separated declaration list must include a variable name after
  every comma.

  Example:
    int a,;

  Diagnostic:
    error: expected variable name after ','
     --> example.cppp:1:7
      |
    1 | int a,;
      |       ^

int requires an integer literal
  CP++ int declarations accept integer literals and arithmetic expressions.
  A string requires an explicit int(...) conversion.

  Example:
    int x = "3";

  Diagnostic:
    error: int requires an integer literal
     --> example.cppp:1:9
      |
    1 | int x = "3";
      |         ^~~
      |
      = help: use `int("3")` to explicitly convert string to int

integer literal overflows CP++ int
  CP++ int is a 64-bit signed integer. Literal values outside that range
  are rejected.

  Example:
    int n = 100000000000000000000000000000000;

  Diagnostic:
    error: integer literal overflows CP++ int
     --> example.cppp:1:9
      |
    1 | int n = 100000000000000000000000000000000;
      |         ^~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

removed bigint and bigfloat types
  bigint and bigfloat have been removed from CP++. Use int or float instead.

  Example:
    bigint x = 123;

  Diagnostic:
    error: bigint has been removed from CP++; use int or float instead
     --> example.cppp:1:1
      |
    1 | bigint x = 123;
      | ^~~~~~

primitive expects 0 subtypes
  Generic syntax is not supported on current primitive CP++ types. The internal
  type tree can represent subtype children for future work, but int, float,
  char, and bool currently have arity 0.

  Example:
    int<int> x;

  Diagnostic:
    error: int expects 0 subtypes
     --> example.cppp:1:4
      |
    1 | int<int> x;
      |    ^

string type
  string is a built-in CP++ type that lowers to List<char>. It carries the
  same List operations such as indexing, slicing, add(...), len(...), in, and
  find(...), but print(...) displays it as normal text instead of a bracketed
  char list.

  Example:
    string s = "hello";
    s.add('!');
    print(s);

string expects 0 subtypes
  string is already a complete type name and does not take generic arguments.

  Example:
    string<int> s;

  Diagnostic:
    error: string expects 0 subtypes
     --> example.cppp:1:7
      |
    1 | string<int> s;
      |       ^

List expects 1 subtype
  List is a generic type constructor and must include exactly one element type.
  Write List<int>, List<char>, or a nested form like List<List<int>>.

  Example:
    List a;
    List<> b;
    List<int, int> c;

  Diagnostic:
    error: List expects 1 subtype like List<int>
     --> example.cppp:1:1
      |
    1 | List a;
      | ^~~~

    error: List expects 1 subtype like List<int>
     --> example.cppp:2:1
      |
    2 | List<> b;
      | ^~~~

    error: List expects 1 subtype
     --> example.cppp:3:9
      |
    3 | List<int, int> c;
      |         ^

context-aware generic type suggestion
  A generic declaration beginning with an unknown name is compared with
  built-in and declared types, including generic constructors.

  Example:
    Lst<int> x;

  Diagnostic:
    error: unsupported statement
     --> example.cppp:1:1
      |
    1 | Lst<int> x;
      | ^~~
      |
      = help: did you mean 'List'?

List literals
  A List declaration can be initialized with square-bracket list literal
  syntax. The declaration's List<T> target decides the element type, so
  empty literals like [] are allowed when the destination type is known.
  Nested literals work for nested List types.

  Example:
    List<bool> even = [true, false, true];
    List<int> empty = [];
    List<List<int>> grid = [[1, 2], [3]];

list truthiness
  List values can be used anywhere CP++ expects a bool. A List is false when
  empty and true when nonempty. Nonempty list literals such as [1] follow the
  same rule.

  Example:
    List<int> values = [1];
    if (values) {
        print("nonempty");
    }

    if ([1]) {
        print("also nonempty");
    }

true and false literals
  true and false are built-in bool literals in expressions and declarations.

  Example:
    bool ok = true;
    if (!false) {
        print(ok);
    }

empty list literal needs a declared List type
  [] by itself does not carry an element type. Use it in a declaration with a
  List<T> target such as List<int> values = [], or in another place where the
  destination List type is already known, such as nested List literals and
  List.add(...).

  Example:
    if ([]) {
        print(1);
    }

  Diagnostic:
    error: empty list literal needs a declared List type
     --> example.cppp:1:5
      |
    1 | if ([]) {
      |     ^

cannot implicitly convert <from> to <to> in list literal
  Each list literal element must match the destination List element type, using
  normal CP++ implicit-conversion rules.

  Example:
    List<int> values = [1, 2.5];

  Diagnostic:
    error: cannot implicitly convert float to int in list literal
     --> example.cppp:1:24
      |
    1 | List<int> values = [1, 2.5];
      |                        ^~~

expected expression after ',' in list literal
  A comma inside a list literal must be followed by another element.

  Example:
    List<int> values = [1,];

  Diagnostic:
    error: expected expression after ',' in list literal
     --> example.cppp:1:22
      |
    1 | List<int> values = [1,];
      |                      ^

unclosed bracket in list literal
  A list literal opened with '[' but did not close with ']'.

  Example:
    List<int> values = [1, 2;

  Diagnostic:
    error: unclosed bracket in list literal
     --> example.cppp:1:20
      |
    1 | List<int> values = [1, 2;
      |                    ^
      |
      = help: add `]` to close the delimiter

List values must use a list literal like [1, 2] or another List expression
  A List declaration cannot be initialized from a non-List scalar value.

  Example:
    List<int> values = 3;

  Diagnostic:
    error: List values must use a list literal like [1, 2] or another List expression
     --> example.cppp:1:20
      |
    1 | List<int> values = 3;
      |                    ^

List add
  Lists support add(value) to append at the end and add(value, index) to
  insert at a specific location. The inserted value must match the List element
  type, using the same implicit-conversion rules as assignment.

  Example:
    List<int> values;
    values.add(1);
    values.add(2, 0);

cannot add <from> to List<...>
  The value passed to add(...) must be compatible with the List element type.

  Example:
    List<int> values;
    float bad = 1.5;
    values.add(bad);

  Diagnostic:
    error: cannot add float to List<int>
     --> example.cppp:3:12
      |
    3 | values.add(bad);
      |            ^~~

List remove
  Lists support remove() to pop the last element, and remove(index) to remove
  an element at a specific zero-based index.

  Example:
    List<int> values = [1, 2, 3];
    values.remove();
    values.remove(0);

remove() expects no arguments or index
  remove(...) accepts either no arguments or exactly one index expression.

  Example:
    List<int> values = [1];
    values.remove(true, 0);

  Diagnostic:
    error: remove() expects no arguments or index
     --> example.cppp:2:15
      |
    2 | values.remove(true, 0);
      |               ^~~~

List sort and reverse
  Lists support sort() to sort in place and reverse() to reverse in place.
  sort() uses the default ordering for the List element type and does not
  accept a custom comparator.

  Example:
    List<int> values = [3, 1, 2];
    values.sort();
    values.reverse();

sort() does not take arguments
  sort() only sorts the whole List in place and does not accept arguments.

  Example:
    List<int> values = [3, 1, 2];
    values.sort(0);

  Diagnostic:
    error: sort() does not take arguments
     --> example.cppp:2:13
      |
    2 | values.sort(0);
      |             ^

reverse() does not take arguments
  reverse() only reverses the whole List in place and does not accept
  arguments.

  Example:
    List<int> values = [3, 1, 2];
    values.reverse(0);

  Diagnostic:
    error: reverse() does not take arguments
     --> example.cppp:2:16
      |
    2 | values.reverse(0);
      |                ^

list index must be int
  The second add(...) argument and the remove(index) argument must be int
  values, or something CP++ can implicitly convert to int.

  Example:
    List<int> values;
    values.add(1, 1.5);

  Diagnostic:
    error: list index must be int
     --> example.cppp:2:15
      |
    2 | values.add(1, 1.5);
      |               ^~~

list indexed variables
  A List element accessed with list[index] behaves like a normal mutable
  variable in assignments and updates. It can appear on the left side of
  `=`, compound assignment like `+=`, prefix/postfix `++` and `--`, and can
  receive target-typed `input()` directly.

  Example:
    List<int> values = [1, 2, 3];
    values[1] += 4;
    values[0]++;
    values[2] = input();

  The same rule applies recursively to nested List elements like
  `grid[i][j]`.

List indexing
  A List value can be indexed with square brackets using a zero-based int
  index. Negative indexes are also supported, so list[-1] means the last
  element and list[-2] means the second-to-last element. In --run mode, CP++
  checks that the resolved index is in range and reports a readable runtime
  error if it is not. In submit-style codegen, indexing lowers directly to
  ordinary C++ indexing after the negative-index adjustment.

  Example:
    List<int> values;
    values.add(4);
    print(values[0]);

List slicing
  A List value can be sliced with Python-style [start:end] syntax. This
  returns a brand new List containing indices in the half-open range
  [start, end). Negative bounds are allowed and count from the end of the
  List. If the normalized start is greater than or equal to the normalized
  end, the result is an empty List.

  Example:
    List<int> values = [1, 2, 3, 4];
    print(values[1:3]);
    print(values[1:-1]);

slicing requires a List value
  Slice syntax can only be used on a List expression.

  Example:
    int x = 3;
    print(x[0:1]);

  Diagnostic:
    error: slicing requires a List value
     --> example.cppp:2:8
      |
    2 | print(x[0:1]);
      |        ^

slice start must be int
  The start bound in list[start:end] must be an int expression.

  Example:
    List<int> values = [1, 2];
    print(values[true:false]);

  Diagnostic:
    error: slice start must be int
     --> example.cppp:2:14
      |
    2 | print(values[true:false]);
      |              ^~~~

slice end must be int
  The end bound in list[start:end] must be an int expression.

  Example:
    List<int> values = [1, 2];
    print(values[0:true]);

  Diagnostic:
    error: slice end must be int
     --> example.cppp:2:16
      |
    2 | print(values[0:true]);
      |                ^~~~

unclosed bracket in list slice
  A list slice opened with '[' but did not close with ']'.

  Example:
    print(values[1:3);

  Diagnostic:
    error: unclosed bracket in list slice
     --> example.cppp:1:13
      |
    1 | print(values[1:3);
      |             ^
      |
      = help: add `]` to close the delimiter

List assignment
  List elements can be assigned with square-bracket indexing. This updates the
  existing element in O(1) time.

  Example:
    List<int> values = [1, 2, 3];
    values[1] = 9;

index assignment requires a List value
  Square-bracket assignment can only target a List.

  Example:
    int x = 3;
    x[0] = 1;

  Diagnostic:
    error: indexing requires a List value
     --> example.cppp:2:2
      |
    2 | x[0] = 1;
      |  ^

list index must be int in indexed assignment and updates
  Indexed assignments and updates use the same int index rule as indexed
  reads. This includes plain assignment, compound assignment, and ++/-- on a
  List element.

  Example:
    List<int> values = [1, 2, 3];
    values[true] += 1;

  Diagnostic:
    error: list index must be int
     --> example.cppp:2:7
      |
    2 | values[true] += 1;
      |       ^

List addition
  CP++ supports `A + B` for List values of the same type. This returns a brand
  new List containing all elements of A followed by all elements of B, without
  modifying either input List.

  Example:
    List<int> a = [1, 2];
    List<int> b = [3, 4];
    List<int> both = a + b;

List append assignment
  CP++ supports `A += B` for List values of the same type. This appends all
  elements of B onto the end of A in place. `+=` is still an assignment
  statement, not an expression, so forms like `if (a += b)` are rejected at
  compile time.

  Example:
    List<int> a = [1, 2];
    List<int> b = [3, 4];
    a += b;

cannot append <from> to <to>
  List append assignment requires the right side to be a List of the same
  element type as the left side.

  Example:
    List<int> a = [1];
    List<float> b = [2.5];
    a += b;

  Diagnostic:
    error: cannot append List<float> to List<int>
     --> example.cppp:3:6
      |
    3 | a += b;
      |      ^

List printing
  print(...) can print List values directly. A printed List uses the same
  bracketed format as a list literal, and nested Lists print recursively.

  Example:
    List<int> values = [1, 2];
    List<List<int>> grid = [[1], [2, 3]];
    print(values);
    print(grid);

  Output:
    [1, 2]
    [[1], [2, 3]]

string printing
  print(...) prints string values and string literals as ordinary text, not as
  bracketed Lists of chars.

  Example:
    string name = "hi";
    print(name);
    print("there");

  Output:
    hi
    there

len(list)
  len(...) returns the number of elements in a List, Set, or Map as an int.
  Strings still work through their List<char> lowering.

  Example:
    List<int> values;
    print(len(values));

min(list), max(list), and sum(list)
  min(list) and max(list) return the smallest or largest element of a List.
  sum(list) adds every element of a numeric List and returns the total. For
  List<float> the result is float; for List<bool>, List<char>, and List<int>
  the result is int. These functions accept List expressions such as list
  literals and concatenated Lists, not just named variables.

  Example:
    List<int> values = [3, 1, 2];
    print(min(values), max(values), sum(values));

in operator
  CP++ supports Python-style membership checks with `value in list`. The
  result is bool, so it can be printed directly or used in conditions.
  Empty Lists simply return false. When the left side is also a List of the
  same type, CP++ performs sublist search, so `[2, 3] in [1, 2, 3, 4]` is
  true. Sublist search uses a linear-time KMP-style search over the two Lists.
  If the left List cannot possibly appear in the right List because of type or
  length, the result is just false.

  Example:
    List<int> values = [1, 2, 3];
    if (2 in values) {
        print("found");
    }

    List<int> pattern = [2, 3];
    print(pattern in values);

find() on Lists
  CP++ supports `list.find(x)` to return every zero-based index where `x`
  appears, and `list.find(sublist)` to return every starting index where the
  sublist appears. This works with literals and variables, including nested
  Lists. If there are no matches, the result is an empty List<int>.

  Example:
    List<int> values = [1, 2, 1, 2];
    print(values.find(2));
    print(values.find([1, 2]));

foreach loops
  CP++ supports foreach loops with `for (T x in list) { ... }`. The loop
  variable is declared from the given type and takes each List element value
  in order. If the List is empty, the loop body is skipped.

  Example:
    List<int> values = [1, 2, 3];
    for (int x in values) {
        print(x);
    }

indexing requires a List value
  Square-bracket indexing can only be used on a List.

  Example:
    int x = 3;
    print(x[0]);

  Diagnostic:
    error: indexing requires a List value
     --> example.cppp:2:8
      |
    2 | print(x[0]);
      |        ^

unclosed bracket in list index
  A list indexing expression opened with '[' but did not close with ']'.

  Example:
    print(values[0);

  Diagnostic:
    error: unclosed bracket in list index
     --> example.cppp:1:13
      |
    1 | print(values[0);
      |             ^
      |
      = help: add `]` to close the delimiter

len() expects a List, Heap, Set, or Map value

    error: max() expects a List, Set, or Map value, or a list of multiple values of the same type

right side of 'in' must be a List
  The membership operator only works with a List on the right side.

  The left side of `in` must be implicitly comparable to the List element
  type. Narrowing conversions still require an explicit cast.

    float needle = 1.5;

  Diagnostic:
    error: cannot check membership of float in List<int>
     --> example.cppp:3:14
      |
    3 | print(needle in values);
      |              ^~

cannot find <from> in <List<...>>
  find(...) accepts either one element compatible with the List element type,
  or a sublist of the exact same List type as the receiver.

  Example:
    List<int> values = [1, 2];
    print(values.find(1.5));

  Diagnostic:
    error: cannot find float in List<int>
     --> example.cppp:2:14
      |
    2 | print(values.find(1.5));
      |              ^~~~

for-in expects a List value

invalid list index
  In --run mode, list[index] and list[index] = value report a runtime error
  when index is negative or greater than or equal to len(list).

  Example:

  Diagnostic:
    error: runtime error: invalid list index
     --> example.cppp:3:13
      |
    3 | print(values[3]);
      |             ^

    List<int> values = [];

  Diagnostic:
    error: runtime error: cannot take max of empty list
     --> example.cppp:2:7

    2 | print(max(values));
      |       ^~~

cannot take min/max of single non-list item
  If min/max has one argument it must be a single List, Set, or Map.

  Example:
    print(max(7));

  Diagnostic:
    error: max() expects a List, Set, or Map value, or a list of multiple values of the same type
     --> example.cppp:1:7

      |       ^~~

cannot take min/max of a seqwuence of mixed type
  Types must not be mixed in a sequence passed to max or min.

  Example:

  Diagnostic:
    error: min() expects all items in sequence to be of same type
     --> example.cppp:1:7
      |
    1 | print(min(1,2,2.2));
      |       ^~~

cannot implicitly convert string to char
  Double-quoted strings are still string values, even when they contain only

Functions
---------

user-defined functions
  CP++ supports top-level functions of the form `T name(T a, T b){ ... }`.
  Parameters and return values use normal CP++ type rules, and `void`

Operator support
----------------

shift operators
  << and >> are supported for int, char, and bool expression operands.
  The result is an int value.

  Example:
    int shifted = 1 << 4;

bitwise operators
  &, |, and ^ are supported for int, char, and bool expression operands.
  The result is an int value.

  Example:
    int flags = 5 & 3;

boolean operators
  &&, ||, and ! are supported for CP++ value expressions. The result is bool.

  Example:
    bool ok = true && !false;

compound assignment operators
  CP++ supports compound assignment forms for supported binary operators,
  including +=, -=, *=, /=, %=, <<=, >>=, &=, |=, ^=, &&=, and ||=.

  Example:
    int flags = 1;
    flags <<= 3;
    flags ^= 2;
    bool ok = true;
    ok &&= flags > 0;

increment and decrement operators
  ++ and -- are supported in prefix and postfix form for mutable char, int,
  and float variables. They can be used as statements or inside expressions,
  including if and while conditions.

  Example:
    int n = 3;
    while (n--) {
        print(n);
    }

    ++n;

comparison operators
  <, <=, >, >=, ==, and != are supported for int, float, char, and bool
  values. int and float values can be compared with each other. Lists of the
  same CP++ type are also comparable in lexicographic order, including nested
  lists such as List<List<int>>.

  Example:
    bool less = 1 < 2;
    bool same = 'A' == 'A';
    float f = 1.5;
    bool lessFloat = f < 2.0;
    List<int> a = [1];
    List<int> b = [1, 2];
    bool shorterFirst = a < b;

cannot use '<operator>' with <left> and <right>
  An operator was used with operand types that CP++ does not support.

  Example:
    float f = 1.2;
    int bad = f & 3;

  Diagnostic:
    error: cannot use '&' with float and int
     --> example.cppp:2:13
      |
    2 | int bad = f & 3;
      |             ^

  Increment and decrement operators require a mutable numeric or char
  variable. bool cannot be incremented or decremented.

  Example:
    bool ok = true;
    ok++;

  Diagnostic:
    error: cannot use '++' with bool
     --> example.cppp:2:3
      |
    2 | ok++;
      |   ^~

expected variable before '++'
  Postfix increment and decrement must be applied to a mutable variable.

  Example:
    1++;

  Diagnostic:
    error: expected variable before '++'
     --> example.cppp:1:2
      |
    1 | 1++;
      |  ^~

expected variable after '++'
  Prefix increment and decrement must be followed by a mutable variable.

  Example:
    ++1;

  Diagnostic:
    error: expected variable after '++'
     --> example.cppp:1:1
      |
    1 | ++1;
      | ^~

cannot compare <left> and <right>
  The two operand types cannot be compared by CP++.

  Example:
    List<int> a = [1];
    List<float> b = [1.0];
    bool bad = a < b;

Control flow
------------

if, else if, else, while, for, and rep blocks
  CP++ supports C++-style if, else if, else, while, and for block outlines,
  plus rep(count). Conditions must be bool expressions or values that can be
  implicitly converted to bool, and block bodies use normal CP++ statements.

  Example:
    int a = 1;
    int b = 2;
    if (a < b) {
        print(a);
    } else if (a == b) {
        print(0);
    } else {
        print(b);
    }

    while (a < b) {
        a = a + 1;
    }

    for (int i = 0; i < 3; i++) {
        print(i);
    }

    rep(3) {
        print("again");
    }

statement AST backed control flow
  CP++ now parses structured control-flow statements through a statement AST
  before lowering them. This keeps classic for-loops, foreach loops, if/else,
  while, rep, and closing-brace continuations like `} else if (...) {`
  recognized explicitly instead of only by an ordered statement chain.

  Example:
    int total = 0;
    for (int i = 0; i < 3; i++) {
        total += i;
    }
    if (total == 3) {
        print(total);
    } else {
        print(0);
    }

break and continue
  CP++ supports `break;` and `continue;` inside any loop body. `break` exits
  the nearest loop immediately. `continue` skips to the next iteration of the
  nearest loop.

  Example:
    for (int i = 0; i < 5; i++) {
        if (i == 2) {
            continue;
        }
        if (i == 4) {
            break;
        }
        print(i);
    }

loop nobreak
  CP++ supports Python-style loop `nobreak` blocks on `for`, foreach, `while`,
  and `rep`. The `nobreak` block runs only when the loop finishes normally and
  does not run if the loop exits through `break`.

  Example:
    int x = 0;
    while (x < 3) {
        x++;
    } nobreak {
        print("finished");
    }

submit-mode loop-nobreak optimization
  In --submit mode, CP++ only keeps the internal loop-completion boolean for
  loops that actually have a following loop `nobreak`. Ordinary loops without a
  loop `nobreak` do not carry that extra helper state in generated C++.

structured control-flow syntax errors
  Malformed if, else if, while, rep, for, and for-in headers are reported by
  their own parsers before the compiler falls back to unrelated declaration or
  statement errors.

  Example:
    if true {
        print(1);
    }

  Diagnostic:
    error: expected '(' after if
     --> example.cppp:1:3
      |
    1 | if true {
      |   ^

expected condition
  An if or else if block has an empty condition.

  Example:
    if () {
        print(1);
    }

  Diagnostic:
    error: expected condition
     --> example.cppp:1:5
      |
    1 | if () {
      |     ^

missing '{' after if

Input

input()
  input() is target-typed by declarations and assignments. It reads one value
  from standard input using the destination type. In multi-declarations and
  multi-assignments, one input value is read for each destination variable.

  Example:
    int x = input();
    x = input();

    int a,b,c = input();
    a,b,c = input();

input must be called as input()
  input is a built-in input call, not a variable name. It must include the
  empty parenthesized call.

  Example:
    int x = input;

  Diagnostic:

     --> example.cppp:1:9

input() does not take arguments
  input() is target-typed by the destination variable, so it does not accept
  arguments inside the parentheses.

  Example:
    int x = input(123);

  Diagnostic:
    error: input() does not take arguments
     --> example.cppp:1:13
      |
    1 | print(input(123));
      |             ^~~

     --> example.cppp:1:14

  comes from the assignment or declaration target.

list input
  List targets can read directly from input by giving one size per List
  dimension. For nested Lists, you may also omit the final dimension so each
  innermost one-dimensional List is read with line-style input(). CP++ reads
  elements in row-major order into the requested shape. Size expressions can
  be integer literals or int-compatible variables.

  Example:
    List<int> line = input(4);
    int rows = 2;
    int cols = 3;
    List<List<int>> grid = input(rows, cols);
    List<List<int>> ragged = input(rows);

string input
  string targets can read either a whitespace-delimited word with input(), or
  exactly n characters with input(n). string input(n) reads by character
  rather than by whitespace-delimited element tokens.

  Example:
    string word = input();
    string chunk = input(3);

input(count) is only supported for List targets
  Size arguments belong to List input. Scalar targets still use plain input().

  Example:
    int x = input(3);

  Diagnostic:
    error: input(count) is only supported for List targets
     --> example.cppp:1:15
      |
    1 | int x = input(3);
      |               ^

List line input
  A one-dimensional List target can use input() with no sizes. CP++ reads one
  whole input line, splits it on whitespace, and stores every parsed element.

  Example:
    List<int> values = input();

List input() without sizes only supports one-dimensional Lists; use input(n) or one size per List dimension
  Nested Lists still need explicit sizes so CP++ knows the shape to read.

  Example:
    List<List<int>> values = input();

  Diagnostic:
    error: List input() without sizes only supports one-dimensional Lists; use input(n) or one size per List dimension
     --> example.cppp:1:26
      |
    1 | List<List<int>> values = input();

submit helper pruning
  In --submit mode, CP++ emits only the generated runtime types and individual
  helper functions that the translated program actually references. A string
  literal, for example, keeps the CP++ char type and string printer but omits
  unrelated char input, output, and increment/decrement helpers. Class methods
  and overloads are pruned individually, so using List.size() or `==` does not
  retain unrelated methods or the other comparison operators. Requirements in
  unreachable functions are ignored. Entire unused classes and unreachable
  top-level functions are omitted too. The remaining submit output is
  whitespace-minified: comments and formatting whitespace are removed, while
  literal contents and separators required by the C++ lexer are preserved.
  Pass `--readable` after `--submit` to keep the same pruning but skip only the
  final whitespace-compaction pass.

  Example:
    List<int> values = [1, 2];
    values.add(3);
    print(len(values));

  Invalid CP++ is rejected before pruning, so an unused method is not a way to
  hide a source error.

  Error example:
    void unusedBadCode() {
        List<int> values = [1, 2];
        values.add("three");
    }

  Diagnostic:
    error: cannot add string to List<int>
     --> example.cppp:3:16
      |
    3 |         values.add("three");
      |                ^~~

runtime diagnostic model
  CP++ has two runtime-oriented compilation targets. --run emits checked C++
  for readable CP++ runtime diagnostics and catches those errors in generated
  main. --submit emits lean C++ for submission and does not add readable
  runtime-error checks. Both modes otherwise lower the same CP++ program.

  Example:
    int total=18;
    int zero=0;
    int x=total/zero;

  Diagnostic:
    error: runtime error: division by zero
     --> example.cppp:3:12
      |
    3 | int x=total/zero;
      |            ^

  In --run mode, integer division by zero is checked and reported as a readable
  CP++ runtime error. In --submit mode, division is emitted as ordinary C++.

  Example:
    int numerator=12;
    int denominator=0;
    int answer=numerator/denominator;

  Diagnostic:
    error: runtime error: division by zero
     --> example.cppp:3:21
      |
    3 | int answer=numerator/denominator;
      |                     ^

  In --run mode, integer modulo by zero is checked and reported as a readable
  CP++ runtime error. In --submit mode, modulo is emitted as ordinary C++.

  Example:
    int x = 4 % 0;

  Diagnostic:
    error: runtime error: modulo by zero
     --> example.cppp:1:11
      |
    1 | int x = 4 % 0;
      |           ^

  cases are checked and reported as readable integer overflow diagnostics. In
  --submit mode, arithmetic is emitted as ordinary C++.

  Example:

     --> example.cppp:2:7

Whitespace-insensitive parsing
------------------------------

canonical whole-source token stream
  CP++ tokenizes the complete source file once before statement parsing. Every
  token keeps its original line, column, and byte offsets; comments and block
  braces are represented explicitly rather than discovered by later rescans.
  Statement parsing receives the canonical fragment token view, and control-flow
  expressions are passed to the expression parser as token slices without a
  second lexical scan. Downstream statement, function, declaration, assignment,
  collection, print, input, lvalue, and expression parsers accept token streams
  only; the deprecated string parser overloads and fallback rescans are removed.

  Example:
    int total = 0;
    List<int> values = [1, 2, 3]; // one canonical comment token
    for (int value in values) {
        total += value;
    }
    print(total);

token-stream expression error
  Malformed token substreams are diagnosed by the CP++ expression parser. They
  are never passed through a second string lexer or exposed as raw C++ errors.

  Example:
    int total = 1;
    if (total + ) {
        total++;
    }

  Diagnostic:
    error: expected expression

unrecognized source token
  A character that is not part of CP++ syntax is rejected by the canonical
  tokenizer before statement parsing continues.

  Example:
    int value = 1;
    if (value > 0) {
        @;
    }
    print(value);

  Diagnostic:
    error: unrecognized token '@'

lexer whitespace
  The lexer skips whitespace and does not emit whitespace tokens. Parser
  decisions should be made from tokens, not from the amount of space between
  tokens.

  Example:
    int x
    =8
    ;
    int y=2;
    int z=(x+y)*3/2%7;
    print(z);

for-header semicolons
  Semicolons inside for(...) headers are part of the header, not statement
  separators. This works even when the header has no spaces.

  Example:
    for(int i=0;i<3;i++){
    print(i);
    }

block brace whitespace
  Control-flow opening braces may appear on the same line as the header or on
  their own line. Empty blocks such as if(true){} are accepted.

  Example:
    if(true){}
    while(n<2)
    {
    n++;
    }

empty condition
  Flexible block brace placement does not make an empty condition valid.

  Example:
    if()
    {
    print(1);
    }

  Diagnostic:
    error: expected condition
     --> example.cppp:1:4
      |
    1 | if()
      |    ^

semicolon-separated statements
  Multiple semicolon-terminated statements may appear on the same physical
  source line and are lowered as separate C++ statements.

  Example:
    int a = 0; int b = 1; print(a,b);

Function variable errors
------------------------

partial function cannot initialize a non-function value
  A partially supplied function produces another function, not its final return value.

  Example:
    int add(int left, int right){ return left + right; }
    int value = add(1);

  Diagnostic:
    error: cannot implicitly convert int(int) to int

cannot reference an undeclared function
  A function variable initializer must name a built-in or declared function.

  Example:
    int(int) operation = missing;

  Diagnostic:
    error: use of undeclared variable 'missing'

free function return type mismatch
  The function's return type must match the function variable type.

  Example:
    int add(int left, int right){ return left + right; }
    float(int, int) operation = add;

  Diagnostic:
    error: cannot implicitly convert int(int, int) to float(int, int)

free function parameter count mismatch
  The function's parameter count must match the function variable type.

  Example:
    int add(int left, int right){ return left + right; }
    int(int) operation = add;

  Diagnostic:
    error: cannot implicitly convert int(int, int) to int(int)

free function parameter type mismatch
  Every function parameter type must match in order.

  Example:
    int add(int left, int right){ return left + right; }
    int(int, float) operation = add;

  Diagnostic:
    error: cannot implicitly convert int(int, int) to int(int, float)

function variable return type mismatch
  Reassigning a function variable still requires an identical function type.

  Example:
    int add(int left, int right){ return left + right; }
    int(int, int) source = add;
    float(int, int) operation = source;

  Diagnostic:
    error: cannot implicitly convert int(int, int) to float(int, int)

function variable parameter count mismatch
  Function variable aliases must have the same number of parameters.

  Example:
    int add(int left, int right){ return left + right; }
    int(int, int) source = add;
    int(int) operation = source;

  Diagnostic:
    error: cannot implicitly convert int(int, int) to int(int)

function variable parameter type mismatch
  Function variable aliases must have matching parameter types.

  Example:
    int add(int left, int right){ return left + right; }
    int(int, int) source = add;
    int(int, float) operation = source;

  Diagnostic:
    error: cannot implicitly convert int(int, int) to int(int, float)

function argument return type mismatch
  A higher-order function checks the return type of a supplied function.

  Example:
    int add(int left, int right){ return left + right; }
    void use(float(int, int) operation){}
    use(add);

  Diagnostic:
    error: use expected parameters of float(int, int) type got int(int, int)

function argument parameter count mismatch
  A higher-order function checks the parameter count of a supplied function.

  Example:
    int add(int left, int right){ return left + right; }
    void use(int(int) operation){}
    use(add);

  Diagnostic:
    error: use expected parameters of int(int) type got int(int, int)

function argument parameter type mismatch
  A higher-order function checks every parameter type of a supplied function.

  Example:
    int add(int left, int right){ return left + right; }
    void use(int(int, float) operation){}
    use(add);

  Diagnostic:
    error: use expected parameters of int(int, float) type got int(int, int)

class function field return type mismatch
  A function used for a class field must have the field's return type.

  Example:
    int add(int left, int right){ return left + right; }
    class Box { float(int, int) operation; }
    Box box = Box(add);

  Diagnostic:
    error: cannot use int(int, int) for field 'operation' of Box

class function field parameter count mismatch
  A function used for a class field must have the field's parameter count.

  Example:
    int add(int left, int right){ return left + right; }
    class Box { int(int) operation; }
    Box box = Box(add);

  Diagnostic:
    error: cannot use int(int, int) for field 'operation' of Box

class function field parameter type mismatch
  A function used for a class field must have the field's parameter types.

  Example:
    int add(int left, int right){ return left + right; }
    class Box { int(int, float) operation; }
    Box box = Box(add);

  Diagnostic:
    error: cannot use int(int, int) for field 'operation' of Box

cannot add function values
  Function values do not support arithmetic.

  Example:
    int add(int left, int right){ return left + right; }
    print(add + add);

  Diagnostic:
    error: function values only support calls, assignment, ==, and !=

cannot order function values
  Function values support equality, but not ordering comparisons.

  Example:
    int add(int left, int right){ return left + right; }
    print(add < add);

  Diagnostic:
    error: function values only support calls, assignment, ==, and !=

cannot negate function values
  Function values do not have boolean truthiness.

  Example:
    int add(int left, int right){ return left + right; }
    print(!add);

  Diagnostic:
    error: function values only support calls, assignment, ==, and !=

cannot index function values
  Function values are callable, not indexable.

  Example:
    int add(int left, int right){ return left + right; }
    print(add[0]);

  Diagnostic:
    error: indexing requires a List value

cannot increment function values
  Function values do not support increment or decrement.

  Example:
    int add(int left, int right){ return left + right; }
    add++;

  Diagnostic:
    error: function values only support calls, assignment, ==, and !=

partial function return type mismatch
  A partial function's final return type must match its declared function variable.

  Example:
    int add(int left, int right){ return left + right; }
    float(int) operation = add(1);

  Diagnostic:
    error: cannot implicitly convert int(int) to float(int)

partial function parameter count mismatch
  A partial function type contains exactly its remaining parameters.

  Example:
    int add(int left, int right){ return left + right; }
    int() operation = add(1);

  Diagnostic:
    error: cannot implicitly convert int(int) to int()

partial function parameter type mismatch
  Remaining partial-function parameter types must match their declaration.

  Example:
    int add(int left, int right){ return left + right; }
    int(float) operation = add(1);

  Diagnostic:
    error: cannot implicitly convert int(int) to int(float)

fully evaluated function cannot initialize function variable
  Supplying every argument returns the function result rather than another function.

  Example:
    int add(int left, int right){ return left + right; }
    int(int) operation = add(1, 2);

  Diagnostic:
    error: cannot implicitly convert int to int(int)

ordinary value cannot initialize zero-parameter function
  A zero-parameter function value is still distinct from its return value.

  Example:
    int value = 7;
    int() operation = value;

  Diagnostic:
    error: cannot implicitly convert int to int()

function variable copy mode mismatch
  A function value must preserve whether a reference parameter is copied.

  Example:
    int consume(copy List<int> values){ return len(values); }
    int(List<int>) indirect = consume;

  Diagnostic:
    error: cannot implicitly convert int(copy List<int>) to int(List<int>)

Heaps
-----

heap class requires a comparator
  A class has no default heap order. Provide `bool(Class, Class)`.

  Example:
    class Point { int x; }
    Heap<Point> values;

  Diagnostic:
    error: default cannot compare values of type Point; provide bool(Point, Point) instead

heap push type mismatch
  `push` must receive the Heap element type.

  Example:
    Heap<int> values;
    values.push("bad");

  Diagnostic:
    error: cannot push string to Heap<int>

heap conversion from incompatible List element type
  `Heap(list)` preserves and checks the List element type.

  Example:
    List<string> words = ["x"];
    Heap<int> values = Heap(words);

  Diagnostic:
    error: cannot cast Heap<string> to Heap<int>

heap constructor requires a List
  `Heap(value)` is only a conversion from a List.

  Example:
    Heap<int> values = Heap(7);

  Diagnostic:
    error: cannot cast int to Heap

heap conversion target mismatch
  An explicitly heapified List still must match the destination Heap type.

  Example:
    List<int> source = [1];
    Heap<string> values = Heap(source);

  Diagnostic:
    error: cannot cast Heap<int> to Heap<string>

pop from empty heap
  `pop()` on an empty Heap is a runtime error.

  Example:
    Heap<int> empty;
    empty.pop();

  Diagnostic:
    error: runtime error: cannot pop empty Heap

top from empty heap
  `top()` on an empty Heap is a runtime error.

  Example:
    Heap<int> empty;
    empty.top();

  Diagnostic:
    error: runtime error: cannot take top of empty Heap

invalid runtime input
  In `--run`, input type mismatches report a CP++ runtime error instead of
  silently leaving a default value behind.

  Example:
    int value = input();

  Diagnostic:
    error: runtime error: invalid input: expected int

negative List input size
  A counted List input cannot have a negative size.

  Example:
    List<int> values = input(-1);

  Diagnostic:
    error: runtime error: input() List size cannot be negative
