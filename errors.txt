CP++ Error Documentation
========================

This file documents the native CP++ diagnostics currently produced before
falling back to generated C++ compiler errors.

General syntax
--------------

missing semicolon
  A CP++ statement must end with a semicolon.

  Example:
    print("hello")

  Diagnostic:
    error: missing semicolon

unsupported statement
  The statement is not recognized by the current compiler frontend.
  At the moment, supported statements are primitive declarations,
  assignment statements, print(...) calls, if/else blocks, while loops,
  for loops, and rep loops.

  Example:
    printBinary();

  Diagnostic:
    error: unsupported statement

Primitive type errors
---------------------

primitive type tree
  CP++ stores types internally as a primitive root with a list of subtype
  children. The current user-facing roots are int, float, char, bool,
  string, and List<T>. The primitive roots int, float, char, bool, and
  string each expect zero subtypes, while List expects exactly one subtype.

  Example:
    int x;
    float y;
    char c;
    bool ok;
    string name;
    List<int> values;
    List<List<char>> table;

expected variable name after <type>
  A primitive declaration must provide a valid identifier after the type.

  Example:
    int = 5;

  Diagnostic:
    error: expected variable name after int

variable '<name>' is already declared
  A variable name cannot be declared twice in the same current scope.

  Example:
    int x;
    int x;

  Diagnostic:
    error: variable 'x' is already declared

expected value after '='
  A declaration assignment has an equals sign but no value.

  Example:
    int x =;

  Diagnostic:
    error: expected value after '='

expected ';' or '=' after variable name
  Extra tokens appeared after a variable name in a declaration.

  Example:
    int x y;

  Diagnostic:
    error: expected ';' or '=' after variable name

expected variable name after ','
  A comma-separated declaration list must include a variable name after
  every comma.

  Example:
    int a,;

  Diagnostic:
    error: expected variable name after ','

int requires an integer literal
  CP++ int declarations accept integer literals and arithmetic expressions.
  Non-arithmetic literal values are rejected.

  Example:
    int x = 1.5;

  Diagnostic:
    error: int requires an integer literal

integer literal overflows CP++ int
  CP++ int is a 64-bit signed integer. Literal values outside that range
  are rejected.

  Example:
    int n = 100000000000000000000000000000000;

  Diagnostic:
    error: integer literal overflows CP++ int

removed bigint and bigfloat types
  bigint and bigfloat have been removed from CP++. Use int or float instead.

  Example:
    bigint x = 123;

  Diagnostic:
    error: bigint has been removed from CP++; use int or float instead

primitive expects 0 subtypes
  Generic syntax is not supported on current primitive CP++ types. The internal
  type tree can represent subtype children for future work, but int, float,
  char, and bool currently have arity 0.

  Example:
    int<int> x;

  Diagnostic:
    error: int expects 0 subtypes

string type
  string is a built-in CP++ type that lowers to List<char>. It carries the
  same List operations such as indexing, slicing, add(...), len(...), in, and
  find(...), but print(...) displays it as normal text instead of a bracketed
  char list.

  Example:
    string s = "hello";
    s.add('!');
    print(s);

string expects 0 subtypes
  string is already a complete type name and does not take generic arguments.

  Example:
    string<int> s;

  Diagnostic:
    error: string expects 0 subtypes

List expects 1 subtype
  List is a generic type constructor and must include exactly one element type.
  Write List<int>, List<char>, or a nested form like List<List<int>>.

  Example:
    List a;
    List<> b;
    List<int, int> c;

  Diagnostic:
    error: List expects 1 subtype like List<int>

List literals
  A List declaration can be initialized with square-bracket list literal
  syntax. The declaration's List<T> target decides the element type, so
  empty literals like [] are allowed when the destination type is known.
  Nested literals work for nested List types.

  Example:
    List<bool> even = [true, false, true];
    List<int> empty = [];
    List<List<int>> grid = [[1, 2], [3]];

list truthiness
  List values can be used anywhere CP++ expects a bool. A List is false when
  empty and true when nonempty. Nonempty list literals such as [1] follow the
  same rule.

  Example:
    List<int> values = [1];
    if (values) {
        print("nonempty");
    }

    if ([1]) {
        print("also nonempty");
    }

true and false literals
  true and false are built-in bool literals in expressions and declarations.

  Example:
    bool ok = true;
    if (!false) {
        print(ok);
    }

empty list literal needs a declared List type
  [] by itself does not carry an element type. Use it in a declaration with a
  List<T> target such as List<int> values = [], or in another place where the
  destination List type is already known, such as nested List literals and
  List.add(...).

  Example:
    if ([]) {
        print(1);
    }

  Diagnostic:
    error: empty list literal needs a declared List type

cannot implicitly convert <from> to <to> in list literal
  Each list literal element must match the destination List element type, using
  normal CP++ implicit-conversion rules.

  Example:
    List<int> values = [1, 2.5];

  Diagnostic:
    error: cannot implicitly convert float to int in list literal

expected expression after ',' in list literal
  A comma inside a list literal must be followed by another element.

  Example:
    List<int> values = [1,];

  Diagnostic:
    error: expected expression after ',' in list literal

unclosed bracket in list literal
  A list literal opened with '[' but did not close with ']'.

  Example:
    List<int> values = [1, 2;

  Diagnostic:
    error: unclosed bracket in list literal

List values must use a list literal like [1, 2] or another List expression
  A List declaration cannot be initialized from a non-List scalar value.

  Example:
    List<int> values = 3;

  Diagnostic:
    error: List values must use a list literal like [1, 2] or another List expression

List add
  Lists support add(value) to append at the end and add(value, index) to
  insert at a specific location. The inserted value must match the List element
  type, using the same implicit-conversion rules as assignment.

  Example:
    List<int> values;
    values.add(1);
    values.add(2, 0);

cannot add <from> to List<...>
  The value passed to add(...) must be compatible with the List element type.

  Example:
    List<int> values;
    float bad = 1.5;
    values.add(bad);

  Diagnostic:
    error: cannot add float to List<int>

List remove
  Lists support remove() to pop the last element, and remove(index) to remove
  an element at a specific zero-based index.

  Example:
    List<int> values = [1, 2, 3];
    values.remove();
    values.remove(0);

remove() expects no arguments or index
  remove(...) accepts either no arguments or exactly one index expression.

  Example:
    List<int> values = [1];
    values.remove(true, 0);

  Diagnostic:
    error: remove() expects no arguments or index

List sort and reverse
  Lists support sort() to sort in place and reverse() to reverse in place.
  sort() uses the default ordering for the List element type and does not
  accept a custom comparator.

  Example:
    List<int> values = [3, 1, 2];
    values.sort();
    values.reverse();

sort() does not take arguments
  sort() only sorts the whole List in place and does not accept arguments.

  Example:
    List<int> values = [3, 1, 2];
    values.sort(0);

  Diagnostic:
    error: sort() does not take arguments

reverse() does not take arguments
  reverse() only reverses the whole List in place and does not accept
  arguments.

  Example:
    List<int> values = [3, 1, 2];
    values.reverse(0);

  Diagnostic:
    error: reverse() does not take arguments

list index must be int
  The second add(...) argument and the remove(index) argument must be int
  values, or something CP++ can implicitly convert to int.

  Example:
    List<int> values;
    values.add(1, 1.5);

  Diagnostic:
    error: list index must be int

list indexed variables
  A List element accessed with list[index] behaves like a normal mutable
  variable in assignments and updates. It can appear on the left side of
  `=`, compound assignment like `+=`, prefix/postfix `++` and `--`, and can
  receive target-typed `input()` directly.

  Example:
    List<int> values = [1, 2, 3];
    values[1] += 4;
    values[0]++;
    values[2] = input();

  The same rule applies recursively to nested List elements like
  `grid[i][j]`.

List indexing
  A List value can be indexed with square brackets using a zero-based int
  index. Negative indexes are also supported, so list[-1] means the last
  element and list[-2] means the second-to-last element. In --run mode, CP++
  checks that the resolved index is in range and reports a readable runtime
  error if it is not. In submit-style codegen, indexing lowers directly to
  ordinary C++ indexing after the negative-index adjustment.

  Example:
    List<int> values;
    values.add(4);
    print(values[0]);

List slicing
  A List value can be sliced with Python-style [start:end] syntax. This
  returns a brand new List containing indices in the half-open range
  [start, end). Negative bounds are allowed and count from the end of the
  List. If the normalized start is greater than or equal to the normalized
  end, the result is an empty List.

  Example:
    List<int> values = [1, 2, 3, 4];
    print(values[1:3]);
    print(values[1:-1]);

slicing requires a List value
  Slice syntax can only be used on a List expression.

  Example:
    int x = 3;
    print(x[0:1]);

  Diagnostic:
    error: slicing requires a List value

slice start must be int
  The start bound in list[start:end] must be an int expression.

  Example:
    List<int> values = [1, 2];
    print(values[true:false]);

  Diagnostic:
    error: slice start must be int

slice end must be int
  The end bound in list[start:end] must be an int expression.

  Example:
    List<int> values = [1, 2];
    print(values[0:true]);

  Diagnostic:
    error: slice end must be int

unclosed bracket in list slice
  A list slice opened with '[' but did not close with ']'.

  Example:
    print(values[1:3);

  Diagnostic:
    error: unclosed bracket in list slice

List assignment
  List elements can be assigned with square-bracket indexing. This updates the
  existing element in O(1) time.

  Example:
    List<int> values = [1, 2, 3];
    values[1] = 9;

index assignment requires a List value
  Square-bracket assignment can only target a List.

  Example:
    int x = 3;
    x[0] = 1;

  Diagnostic:
    error: indexing requires a List value

list index must be int in indexed assignment and updates
  Indexed assignments and updates use the same int index rule as indexed
  reads. This includes plain assignment, compound assignment, and ++/-- on a
  List element.

  Example:
    List<int> values = [1, 2, 3];
    values[true] += 1;

  Diagnostic:
    error: list index must be int

List addition
  CP++ supports `A + B` for List values of the same type. This returns a brand
  new List containing all elements of A followed by all elements of B, without
  modifying either input List.

  Example:
    List<int> a = [1, 2];
    List<int> b = [3, 4];
    List<int> both = a + b;

List append assignment
  CP++ supports `A += B` for List values of the same type. This appends all
  elements of B onto the end of A in place. `+=` is still an assignment
  statement, not an expression, so forms like `if (a += b)` are rejected at
  compile time.

  Example:
    List<int> a = [1, 2];
    List<int> b = [3, 4];
    a += b;

cannot append <from> to <to>
  List append assignment requires the right side to be a List of the same
  element type as the left side.

  Example:
    List<int> a = [1];
    List<float> b = [2.5];
    a += b;

  Diagnostic:
    error: cannot append List<float> to List<int>

List printing
  print(...) can print List values directly. A printed List uses the same
  bracketed format as a list literal, and nested Lists print recursively.

  Example:
    List<int> values = [1, 2];
    List<List<int>> grid = [[1], [2, 3]];
    print(values);
    print(grid);

  Output:
    [1, 2]
    [[1], [2, 3]]

string printing
  print(...) prints string values and string literals as ordinary text, not as
  bracketed Lists of chars.

  Example:
    string name = "hi";
    print(name);
    print("there");

  Output:
    hi
    there

len(list)
  len(...) returns the number of elements in a List, Set, or Map as an int.
  Strings still work through their List<char> lowering.

  Example:
    List<int> values;
    print(len(values));

min(list), max(list), and sum(list)
  min(list) and max(list) return the smallest or largest element of a List.
  sum(list) adds every element of a numeric List and returns the total. For
  List<float> the result is float; for List<bool>, List<char>, and List<int>
  the result is int. These functions accept List expressions such as list
  literals and concatenated Lists, not just named variables.

  Example:
    List<int> values = [3, 1, 2];
    print(min(values), max(values), sum(values));

in operator
  CP++ supports Python-style membership checks with `value in list`. The
  result is bool, so it can be printed directly or used in conditions.
  Empty Lists simply return false. When the left side is also a List of the
  same type, CP++ performs sublist search, so `[2, 3] in [1, 2, 3, 4]` is
  true. Sublist search uses a linear-time KMP-style search over the two Lists.
  If the left List cannot possibly appear in the right List because of type or
  length, the result is just false.

  Example:
    List<int> values = [1, 2, 3];
    if (2 in values) {
        print("found");
    }

    List<int> pattern = [2, 3];
    print(pattern in values);

find() on Lists
  CP++ supports `list.find(x)` to return every zero-based index where `x`
  appears, and `list.find(sublist)` to return every starting index where the
  sublist appears. This works with literals and variables, including nested
  Lists. If there are no matches, the result is an empty List<int>.

  Example:
    List<int> values = [1, 2, 1, 2];
    print(values.find(2));
    print(values.find([1, 2]));

foreach loops
  CP++ supports foreach loops with `for (T x in list) { ... }`. The loop
  variable is declared from the given type and takes each List element value
  in order. If the List is empty, the loop body is skipped.

  Example:
    List<int> values = [1, 2, 3];
    for (int x in values) {
        print(x);
    }

indexing requires a List value
  Square-bracket indexing can only be used on a List.

  Example:
    int x = 3;
    print(x[0]);

  Diagnostic:
    error: indexing requires a List value

unclosed bracket in list index
  A list indexing expression opened with '[' but did not close with ']'.

  Example:
    print(values[0);

  Diagnostic:
    error: unclosed bracket in list index

len() expects a List, Set, or Map value
  len(...) only accepts ordered collection expressions.

  Example:
    int x = 3;
    print(len(x));

  Diagnostic:
    error: len() expects a List, Set, or Map value

min() expects a List, Set, or Map value
  min(...) accepts one ordered collection expression, or multiple standalone
  values of the same type.

  Example:
    int x = 3;
    print(min(x));

  Diagnostic:
    error: min() expects a List, Set, or Map value, or a list of multiple values of the same type

max() expects a List, Set, or Map value
  max(...) accepts one ordered collection expression, or multiple standalone
  values of the same type.

  Example:
    int x = 3;
    print(max(x));

  Diagnostic:
    error: max() expects a List, Set, or Map value, or a list of multiple values of the same type

sum() expects a List of numeric values
  sum(...) accepts List<bool>, List<char>, List<int>, and List<float>. Nested
  Lists and other nonscalar values are rejected.

  Example:
    List<List<int>> grid = [[1], [2]];
    print(sum(grid));

  Diagnostic:
    error: sum() expects a List of numeric values

right side of 'in' must be a List
  The membership operator only works with a List on the right side.

  Example:
    int x = 3;
    print(1 in x);

  Diagnostic:
    error: right side of 'in' must be a List

cannot check membership of <from> in <List<...>>
  The left side of `in` must be implicitly comparable to the List element
  type. Narrowing conversions still require an explicit cast.

  Example:
    float needle = 1.5;
    List<int> values = [1, 2];
    print(needle in values);

  Diagnostic:
    error: cannot check membership of float in List<int>

cannot find <from> in <List<...>>
  find(...) accepts either one element compatible with the List element type,
  or a sublist of the exact same List type as the receiver.

  Example:
    List<int> values = [1, 2];
    print(values.find(1.5));

  Diagnostic:
    error: cannot find float in List<int>

for-in expects a List value
  A foreach loop must iterate over a List expression.

  Example:
    int x = 3;
    for (int value in x) {
        print(value);
    }

  Diagnostic:
    error: for-in expects a List value

invalid list index
  In --run mode, list[index] and list[index] = value report a runtime error
  when index is negative or greater than or equal to len(list).

  Example:
    List<int> values;
    values.add(4);
    print(values[3]);

    List<int> other = [1, 2];
    other[5] = 9;

  Diagnostic:
    error: runtime error: invalid list index

cannot remove from empty list
  In --run mode, remove() reports a runtime error when the List is empty.

  Example:
    List<int> values = [];
    values.remove();

  Diagnostic:
    error: runtime error: cannot remove from empty list

cannot take min of empty list
  In --run mode, min(list) reports a runtime error when the List is empty.

  Example:
    List<int> values = [];
    print(min(values));

  Diagnostic:
    error: runtime error: cannot take min of empty list

cannot take max of empty list
  In --run mode, max(list) reports a runtime error when the List is empty.

  Example:
    List<int> values = [];
    print(max(values));

  Diagnostic:
    error: runtime error: cannot take max of empty list

cannot take min/max of single non-list item
  If min/max has one argument it must be a single List, Set, or Map.

  Example:
    print(max(7));

  Diagnostic:
    error: max() expects a List, Set, or Map value, or a list of multiple values of the same type

cannot take min/max of a seqwuence of mixed type
  Types must not be mixed in a sequence passed to max or min.

  Example:
    print(min(1,2,2.2));

  Diagnostic:
    error: min() expects all items in sequence to be of same type

cannot implicitly convert string to char
  Double-quoted strings are still string values, even when they contain only
  one character.

  Example:
    char c = "B";

  Diagnostic:
    error: cannot implicitly convert string to char

unterminated char literal
  A char literal starts with a single quote but does not close.

  Example:
    char c = 'B;

  Diagnostic:
    error: unterminated char literal

unexpected characters after char literal
  Extra characters appeared after a valid char literal.

  Example:
    char c = 'B's;

  Diagnostic:
    error: unexpected characters after char literal

char literal contains too many characters
  A char literal contains more than one character.

  Example:
    char c = 'AB';

  Diagnostic:
    error: char literal contains too many characters

Print errors
------------

unclosed parenthesis in print
  A print call starts with print( but does not close its argument list.

  Example:
    print(x;

  Diagnostic:
    error: unclosed parenthesis in print

empty print argument
  A print call has an empty argument.

  Example:
    print(x, );

  Diagnostic:
    error: empty print argument

unterminated string literal in print
  A print argument starts a string literal but does not close it.

  Example:
    print("hello);

  Diagnostic:
    error: unterminated string literal in print

expected ',' between print arguments
  Print arguments must be separated with commas.

  Example:
    print(wrote char);

  Diagnostic:
    error: expected ',' between print arguments

use of undeclared variable '<name>'
  A bare identifier passed to print must refer to a declared variable.

  Example:
    print(wrote);

  Diagnostic:
    error: use of undeclared variable 'wrote'

expected ',' before flush
  Deprecated. Use end = flush instead of passing flush as a print argument.

  Example:
    print("answer" flush);

  Diagnostic:
    error: use end = flush instead of flush argument

print options must come after all printed values
  The end and delim options may appear in either order, but both must come
  after every actual value being printed.

  Example:
    print("x", end = " ", 1);

  Diagnostic:
    error: print options must come after all printed values

print end must be a string, char, or flush
  print end accepts a string, a char, or flush. end = flush emits a newline
  and flushes the stream.

  Example:
    print("x", end = 1);

  Diagnostic:
    error: print end must be a string, char, or flush

print delim must be a string or char
  print delim accepts only a string or char separator. Unlike end, delim does
  not accept flush.

  Example:
    print([1, 2, 3], delim = flush);

  Diagnostic:
    error: print delim must be a string or char

print delim requires a List value
  The delim option only applies to top-level List printing. Nested list items
  still print with their usual bracketed formatting.

  Example:
    print(123, delim = " ");

  Diagnostic:
    error: print delim requires a List value

print requires at least one value
  print must receive at least one printable value before any end option.

  Example:
    print(end = " ");

  Diagnostic:
    error: print requires at least one value

print end option
  print ends with a newline by default. The end option changes the ending.
  end = flush means newline plus flush.

  Example:
    print("hi");
    print("hi", end = " ");
    print("hi", end = flush);

print delim option
  print(list, delim = value) prints the top-level List elements separated by a
  string or char delimiter. This leaves nested Lists printed normally, so
  `print([[1], [2]], delim = " ")` becomes `[1] [2]`.

  Example:
    print([1, 2, 3], delim = " ");
    print("abc", delim = '-');

empty print
  print() is allowed and emits a single newline.

  Example:
    print();

describe
  describe prints the expression text followed by its value. It accepts any
  CP++ expression and evaluates it once before printing, so it works for
  indexing, slicing, find(...), arithmetic, and future expression forms too.

  Example:
    int x = 3;
    List<int> values = [10, 20, 30];
    string s = "abc";
    describe(x);
    describe(values[1]);
    describe(s);

  Output:
    x: 3
    values[1]: 20
    s: abc

describe requires a value
  describe needs one expression inside the parentheses.

  Example:
    describe();

  Diagnostic:
    error: describe requires a value

Expression and assignment errors
--------------------------------

use of undeclared variable '<name>'
  Arithmetic expressions and assignments must reference declared variables.

  Example:
    int x = missing + 1;

  Diagnostic:
    error: use of undeclared variable 'missing'

expected expression
  An arithmetic operator or assignment has no expression where one is required.

  Example:
    int x = 1 +;

  Diagnostic:
    error: expected expression

unexpected token in expression
  Extra tokens appeared after a complete expression.

  Example:
    int x = 1 2;

  Diagnostic:
    error: unexpected token in expression

unclosed parenthesis in expression
  An expression starts a parenthesized group but does not close it.

  Example:
    int x = (1 + 2;

  Diagnostic:
    error: unclosed parenthesis in expression

expected expression after assignment
  An assignment operator has no value after it.

  Example:
    x +=;

  Diagnostic:
    error: expected expression after assignment

multi-declaration requires the same number of values as variables
  A comma-separated declaration with comma-separated initializers must provide
  exactly one value for each declared variable.

  Example:
    int a,b = 1,2,3;

  Diagnostic:
    error: multi-declaration requires the same number of values as variables

multi-assignment requires the same number of values as targets
  A comma-separated assignment must provide exactly one value for each target,
  unless the right side is input(), which reads one value per target.

  Example:
    int a,b;
    a,b = 1,2,3;

  Diagnostic:
    error: multi-assignment requires the same number of values as targets

cannot implicitly convert <from> to <to>
  CP++ still rejects unrelated assignments when there is no implicit
  conversion path between the source and destination types.

  Example:
    int x = 1;
    List<int> values = x;

  Diagnostic:
    error: cannot implicitly convert int to List<int>

cannot cast int to Set
  Set(x) only accepts List values and infers its element type from that List.

  Example:
    print(Set(7));

  Diagnostic:
    error: cannot cast int to Set

cannot cast List<int> to Map
  Map(x) only accepts a List of Pair values.

  Example:
    List<int> values = [1, 2];
    print(Map(values));

  Diagnostic:
    error: cannot cast List<int> to Map

cannot cast List<int> to List
  List(x) only accepts Set or Map values.

  Example:
    List<int> values = [1, 2];
    print(List(values));

  Diagnostic:
    error: cannot cast List<int> to List

cannot cast List<int> to int
  Explicit casts do not let containers masquerade as primitive values.

  Example:
    print(int([1, 2]));

  Diagnostic:
    error: cannot cast List<int> to int

cannot cast Set<int> to char
  Container values cannot be cast directly to primitive scalars.

  Example:
    print(char({1, 2}));

  Diagnostic:
    error: cannot cast Set<int> to char

cannot cast Map<int, int> to float
  Container values must stay containers unless a specific conversion is
  supported.

  Example:
    print(float({1:2}));

  Diagnostic:
    error: cannot cast Map<int, int> to float

cannot cast List<int> to string
  string(x) only accepts scalar CP++ values, not List, Set, or Map values.

  Example:
    print(string([1, 2]));

  Diagnostic:
    error: cannot cast List<int> to string

unclosed parenthesis in range
  range(...) calls must close their argument list.

  Example:
    print(range(1, 2);

  Diagnostic:
    error: unclosed parenthesis in range

range() arguments must be int
  range(...) only accepts int arguments unless you cast first on purpose.

  Example:
    print(range(1.5));

  Diagnostic:
    error: range() arguments must be int

cannot check membership of string in range
  Range membership only works with int values.

  Example:
    print("x" in range(5));

  Diagnostic:
    error: cannot check membership of string in range

cannot cast List<int> to List<bool>
  List(range) always produces a List<int>, so assigning it to another element
  type is a cast error.

  Example:
    List<bool> flags = List(range(3));

  Diagnostic:
    error: cannot cast List<int> to List<bool>

cannot cast Set<int> to Set<char>
  Set(range) always produces a Set<int>, so assigning it to another element
  type is a cast error.

  Example:
    Set<char> seen = Set(range(3));

  Diagnostic:
    error: cannot cast Set<int> to Set<char>

invalid int string
  int(str) requires str to be a valid base-10 integer representation.

  Example:
    print(int("hello"));

  Diagnostic:
    error: runtime error: invalid int string

invalid char string
  char(str) requires str to contain exactly one character.

  Example:
    print(char("no"));

  Diagnostic:
    error: runtime error: invalid char string

invalid bool string
  bool(str) only accepts `0`, `1`, `true`, or `false`.

  Example:
    print(bool("maybe"));

  Diagnostic:
    error: runtime error: invalid bool string

invalid float string
  float(str) requires a complete decimal representation with digits on both
  sides of any decimal point.

  Example:
    print(float("hello"));

  Diagnostic:
    error: runtime error: invalid float string

invalid float string with trailing dot
  A trailing decimal point like `3.` is not a valid CP++ float string cast.

  Example:
    print(float("3."));

  Diagnostic:
    error: runtime error: invalid float string

Functions
---------

user-defined functions
  CP++ supports top-level functions of the form `T name(T a, T b){ ... }`.
  Parameters and return values use normal CP++ type rules, and `void`
  functions may use bare `return;`.

  Example:
    int square(int x){
        return x * x;
    }
    print(square(5));

expected parameter after ','
  A function declaration parameter list cannot end with a trailing comma.

  Example:
    int add(int x,){
        return x;
    }

  Diagnostic:
    error: expected parameter after ','

unclosed parenthesis in function declaration
  A function header opened `(` but did not close its parameter list.

  Example:
    int add(int x, int y{
        return x + y;
    }

  Diagnostic:
    error: unclosed parenthesis in function declaration

unclosed parenthesis in function call
  A function call opened `(` but did not close it.

  Example:
    print(add(1, 2);

  Diagnostic:
    error: unclosed parenthesis in function call

<name> expected parameters of <types> type got <types>
  Function calls are checked against the declared parameter types at compile
  time, and the diagnostic lists both the expected and actual argument types.

  Example:
    int solve(int x, char y){
        return x + int(y);
    }
    print(solve("hi", 7));

  Diagnostic:
    error: solve expected parameters of int and char type got string and int

<name> expected <n> parameters of <types> type got <m>
  Function calls with the wrong arity report both the expected count and the
  provided count.

  Example:
    int add(int x, int y){
        return x + y;
    }
    print(add(1));

  Diagnostic:
    error: add expected 2 parameters of int and int type got 1

return can only be used inside a function
  `return` is only valid inside a user-defined function body.

  Example:
    return 1;

  Diagnostic:
    error: return can only be used inside a function

non-void function must return a value of type <type>
  A function with a non-void return type cannot use bare `return;`.

  Example:
    int bad(){
        return;
    }

  Diagnostic:
    error: non-void function must return a value of type int

void function cannot return a value
  A `void` function may use `return;` but not `return expr;`.

  Example:
    void bad(){
        return 1;
    }

  Diagnostic:
    error: void function cannot return a value

invalid function return type
  A returned expression must be implicitly convertible to the declared return
  type.

  Example:
    int bad(){
        return "hi";
    }

  Diagnostic:
    error: cannot implicitly convert string to int

deep must precede a collection
  The `deep` modifier is only valid before a container parameter type such as
  `List<int>` or `string`.

  Example:
    void f(deep int x){
        print(x);
    }

  Diagnostic:
    error: deep must precede a collection

Operator support
----------------

shift operators
  << and >> are supported for int, char, and bool expression operands.
  The result is an int value.

  Example:
    int shifted = 1 << 4;

bitwise operators
  &, |, and ^ are supported for int, char, and bool expression operands.
  The result is an int value.

  Example:
    int flags = 5 & 3;

boolean operators
  &&, ||, and ! are supported for CP++ value expressions. The result is bool.

  Example:
    bool ok = true && !false;

compound assignment operators
  CP++ supports compound assignment forms for supported binary operators,
  including +=, -=, *=, /=, %=, <<=, >>=, &=, |=, ^=, &&=, and ||=.

  Example:
    int flags = 1;
    flags <<= 3;
    flags ^= 2;
    bool ok = true;
    ok &&= flags > 0;

increment and decrement operators
  ++ and -- are supported in prefix and postfix form for mutable char, int,
  and float variables. They can be used as statements or inside expressions,
  including if and while conditions.

  Example:
    int n = 3;
    while (n--) {
        print(n);
    }

    ++n;

comparison operators
  <, <=, >, >=, ==, and != are supported for int, float, char, and bool
  values. int and float values can be compared with each other. Lists of the
  same CP++ type are also comparable in lexicographic order, including nested
  lists such as List<List<int>>.

  Example:
    bool less = 1 < 2;
    bool same = 'A' == 'A';
    float f = 1.5;
    bool lessFloat = f < 2.0;
    List<int> a = [1];
    List<int> b = [1, 2];
    bool shorterFirst = a < b;

cannot use '<operator>' with <left> and <right>
  An operator was used with operand types that CP++ does not support.

  Example:
    float f = 1.2;
    int bad = f & 3;

  Diagnostic:
    error: cannot use '&' with float and int

cannot use '++' with <type>
  Increment and decrement operators require a mutable numeric or char
  variable. bool cannot be incremented or decremented.

  Example:
    bool ok = true;
    ok++;

  Diagnostic:
    error: cannot use '++' with bool

expected variable before '++'
  Postfix increment and decrement must be applied to a mutable variable.

  Example:
    1++;

  Diagnostic:
    error: expected variable before '++'

expected variable after '++'
  Prefix increment and decrement must be followed by a mutable variable.

  Example:
    ++1;

  Diagnostic:
    error: expected variable after '++'

cannot compare <left> and <right>
  The two operand types cannot be compared by CP++.

  Example:
    List<int> a = [1];
    List<float> b = [1.0];
    bool bad = a < b;

  Diagnostic:
    error: cannot compare List<int> and List<float>

Control flow
------------

if, else if, else, while, for, and rep blocks
  CP++ supports C++-style if, else if, else, while, and for block outlines,
  plus rep(count). Conditions must be bool expressions or values that can be
  implicitly converted to bool, and block bodies use normal CP++ statements.

  Example:
    int a = 1;
    int b = 2;
    if (a < b) {
        print(a);
    } else if (a == b) {
        print(0);
    } else {
        print(b);
    }

    while (a < b) {
        a = a + 1;
    }

    for (int i = 0; i < 3; i++) {
        print(i);
    }

    rep(3) {
        print("again");
    }

statement AST backed control flow
  CP++ now parses structured control-flow statements through a statement AST
  before lowering them. This keeps classic for-loops, foreach loops, if/else,
  while, rep, and closing-brace continuations like `} else if (...) {`
  recognized explicitly instead of only by an ordered statement chain.

  Example:
    int total = 0;
    for (int i = 0; i < 3; i++) {
        total += i;
    }
    if (total == 3) {
        print(total);
    } else {
        print(0);
    }

break and continue
  CP++ supports `break;` and `continue;` inside any loop body. `break` exits
  the nearest loop immediately. `continue` skips to the next iteration of the
  nearest loop.

  Example:
    for (int i = 0; i < 5; i++) {
        if (i == 2) {
            continue;
        }
        if (i == 4) {
            break;
        }
        print(i);
    }

loop nobreak
  CP++ supports Python-style loop `nobreak` blocks on `for`, foreach, `while`,
  and `rep`. The `nobreak` block runs only when the loop finishes normally and
  does not run if the loop exits through `break`.

  Example:
    int x = 0;
    while (x < 3) {
        x++;
    } nobreak {
        print("finished");
    }

submit-mode loop-nobreak optimization
  In --submit mode, CP++ only keeps the internal loop-completion boolean for
  loops that actually have a following loop `nobreak`. Ordinary loops without a
  loop `nobreak` do not carry that extra helper state in generated C++.

structured control-flow syntax errors
  Malformed if, else if, while, rep, for, and for-in headers are reported by
  their own parsers before the compiler falls back to unrelated declaration or
  statement errors.

  Example:
    if true {
        print(1);
    }

  Diagnostic:
    error: expected '(' after if

expected condition
  An if or else if block has an empty condition.

  Example:
    if () {
        print(1);
    }

  Diagnostic:
    error: expected condition

missing '{' after if
  if headers must end with an opening brace.

  Example:
    if (true)
        print(1);

  Diagnostic:
    error: missing '{' after if

missing '{' after while
  while headers must end with an opening brace.

  Example:
    while (true)
        print(1);

  Diagnostic:
    error: missing '{' after while

missing '{' after rep
  rep headers must end with an opening brace.

  Example:
    rep(3)
        print(1);

  Diagnostic:
    error: missing '{' after rep

missing '{' after for loop
  for and for-in headers must end with an opening brace.

  Example:
    for (int i = 0; i < 3; i++)
        print(i);

  Diagnostic:
    error: missing '{' after for loop

for loop variable scope
  A variable declared in a classic for-loop initializer belongs to that loop's
  scope, so a later loop may reuse the same name.

  Example:
    for (int i = 0; i < 3; i++) {
        print(i);
    }
    for (int i = 0; i < 2; i++) {
        print(i);
    }

for loop must use syntax for (init; condition; step)
  A classic for loop needs exactly two top-level semicolons inside the header.

  Example:
    for (int i = 0 i < 3; i++) {
        print(i);
    }

  Diagnostic:
    error: for loop must use syntax for (init; condition; step)

expected 'in' after loop variable
  A foreach loop must use `for (T x in list)`.

  Example:
    for (int x not in values) {
        print(x);
    }

  Diagnostic:
    error: expected 'in' after loop variable

expected rep count
  rep requires a count expression inside parentheses.

  Example:
    rep() {
        print(1);
    }

  Diagnostic:
    error: expected rep count

rep count must be numeric
  rep count must be a numeric or char/bool value.

  Example:
    rep("bad") {
        print(1);
    }

  Diagnostic:
    error: rep count must be numeric

else without matching if
  An else or else if block must immediately follow a completed if or else if
  block.

  Example:
    else {
        print(1);
    }

  Diagnostic:
    error: else without matching if

nobreak without matching loop
  A `nobreak` block must immediately follow a completed `for`, foreach,
  `while`, or `rep` loop.

  Example:
    nobreak {
        print(1);
    }

  Diagnostic:
    error: nobreak without matching loop

break can only be used inside a loop
  `break;` is only valid when the current statement is inside a `for`,
  foreach, `while`, or `rep` loop body.

  Example:
    break;

  Diagnostic:
    error: break can only be used inside a loop

continue can only be used inside a loop
  `continue;` is only valid when the current statement is inside a `for`,
  foreach, `while`, or `rep` loop body.

  Example:
    continue;

  Diagnostic:
    error: continue can only be used inside a loop

unmatched closing brace
  A closing brace appeared without a matching open if, else if, or else block.

  Example:
    }

  Diagnostic:
    error: unmatched closing brace

unclosed block
  An if, else if, or else block was opened but not closed before the end of
  the file.

  Example:
    if (true) {
        print(1);

  Diagnostic:
    error: unclosed block

Input
-----

input()
  input() is target-typed by declarations and assignments. It reads one value
  from standard input using the destination type. In multi-declarations and
  multi-assignments, one input value is read for each destination variable.

  Example:
    int x = input();
    x = input();

    int a,b,c = input();
    a,b,c = input();

input must be called as input()
  input is a built-in input call, not a variable name. It must include the
  empty parenthesized call.

  Example:
    int x = input;

  Diagnostic:
    error: input must be called as input()

input() does not take arguments
  input() is target-typed by the destination variable, so it does not accept
  arguments inside the parentheses.

  Example:
    int x = input(123);

  Diagnostic:
    error: input() does not take arguments

unclosed parenthesis in input
  An input call starts with input( but does not close the call.

  Example:
    int x = input(;

  Diagnostic:
    error: unclosed parenthesis in input

input() can only be used as the entire value in an assignment or declaration
  input() cannot currently be embedded inside an expression because its type
  comes from the assignment or declaration target.

  Example:
    int x = input() + 3;

  Diagnostic:
    error: input() can only be used as the entire value in an assignment or declaration

list input
  List targets can read directly from input by giving one size per List
  dimension. For nested Lists, you may also omit the final dimension so each
  innermost one-dimensional List is read with line-style input(). CP++ reads
  elements in row-major order into the requested shape. Size expressions can
  be integer literals or int-compatible variables.

  Example:
    List<int> line = input(4);
    int rows = 2;
    int cols = 3;
    List<List<int>> grid = input(rows, cols);
    List<List<int>> ragged = input(rows);

string input
  string targets can read either a whitespace-delimited word with input(), or
  exactly n characters with input(n). string input(n) reads by character
  rather than by whitespace-delimited element tokens.

  Example:
    string word = input();
    string chunk = input(3);

input(count) is only supported for List targets
  Size arguments belong to List input. Scalar targets still use plain input().

  Example:
    int x = input(3);

  Diagnostic:
    error: input(count) is only supported for List targets

List line input
  A one-dimensional List target can use input() with no sizes. CP++ reads one
  whole input line, splits it on whitespace, and stores every parsed element.

  Example:
    List<int> values = input();

List input() without sizes only supports one-dimensional Lists; use input(n) or one size per List dimension
  Nested Lists still need explicit sizes so CP++ knows the shape to read.

  Example:
    List<List<int>> values = input();

  Diagnostic:
    error: List input() without sizes only supports one-dimensional Lists; use input(n) or one size per List dimension

string input needs exactly 1 size argument
  string input with an explicit size accepts exactly one size expression.

  Example:
    string s = input(2, 3);

  Diagnostic:
    error: string input needs exactly 1 size argument

List input needs exactly <n> size arguments
  The number of input sizes must match the number of nested List dimensions,
  except nested List input may omit the final dimension and read each inner
  one-dimensional List with input().

  Example:
    List<int> values = input(1, 2);

  Diagnostic:
    error: List input needs exactly 0 or 1 size argument

input() size must be int
  Each List input size must be an int value or something CP++ can implicitly
  convert to int.

  Example:
    float n = 2.5;
    List<int> values = input(n);

  Diagnostic:
    error: input() size must be int

split method
  list.split(delimiter) breaks a List into a List of sublists. The delimiter
  must be either one element of the List's element type, or another List with
  the exact same type as the first argument. Consecutive delimiters are
  skipped, so they do not produce empty pieces.

  Example:
    List<int> values = [1, 2, 3, 2, 1];
    print(values.split(2));
    string text = "hello  world im gay";
    print(text.split("  "));

split must be called as a method
  The value before `.split()` is the haystack, so it must be a List-like value
  such as List<int> or string.

  Example:
    print(split(123, 2));

  Diagnostic:
    error: split must be called as list.split(delimiter)

split method delimiter must be <element> or <list>
  The split() argument must be either one element of the haystack's
  element type, or another List of the exact same type as the haystack.

  Example:
    List<int> values = [1, 2, 3];
    print(values.split(2.5));

  Diagnostic:
    error: split() delimiter must be int or List<int>

Runtime errors
--------------

structs
  A struct groups public fields and typed methods. Struct values use deep-copy
  assignment, recursive struct fields default to NULL, and field access uses
  normal method-style syntax.

  Example:
    struct Point {
        int x;
        int y;
        void shift(int amount) {
            x += amount;
            y += amount;
        }
    }
    Point point = Point(2, 3);
    point.shift(1);
    print(point);

null struct field access
  A default-initialized struct variable is NULL. Access a field only after
  constructing the struct or checking it against NULL.

  Example:
    struct Point {
        int x;
    }
    Point point;
    print(point.x);

  Diagnostic:
    error: runtime error: cannot access a field on null Point

struct constructor field type
  A constructor value must match the declared field type.

  Example:
    struct Point {
        int x;
    }
    Point point = Point("bad");

  Diagnostic:
    error: cannot use string for field 'x' of Point

unknown struct field
  A struct field must be declared in that struct.

  Example:
    struct Point {
        int x;
    }
    Point point = Point(1);
    print(point.y);

  Diagnostic:
    error: struct Point has no field 'y'

unknown struct method
  A struct method must be declared in that struct.

  Example:
    struct Point {
        int x;
    }
    Point point = Point(1);
    point.move();

  Diagnostic:
    error: struct Point has no method 'move'

struct method argument type
  Method arguments must match the declared parameter types.

  Example:
    struct Counter {
        int x;
        void add(int amount) {
            x += amount;
        }
    }
    Counter counter = Counter(0);
    counter.add("bad");

  Diagnostic:
    error: cannot use string as int for add()

struct field scope
  Struct fields are only available through a struct value outside a method.

  Example:
    struct Point {
        int x;
    }
    print(x);

  Diagnostic:
    error: use of undeclared variable 'x'

method local scope
  Variables declared inside a method do not escape that method.

  Example:
    struct Point {
        int x;
        void set() {
            int local = 1;
            x = local;
        }
    }
    print(local);

  Diagnostic:
    error: use of undeclared variable 'local'

null struct method call
  Calling a method on a NULL struct is a runtime error. Check against NULL or
  construct the value first.

  Example:
    struct Counter {
        int x;
        void increment() {
            x++;
        }
    }
    Counter counter;
    counter.increment();

  Diagnostic:
    error: runtime error: cannot call increment() on null Counter

submit helper pruning
  In --submit mode, CP++ emits only the generated runtime types and individual
  helper functions that the translated program actually references. A string
  literal, for example, keeps the CP++ char type and string printer but omits
  unrelated char input, output, and increment/decrement helpers.

  Example:
    int x = input();
    print(x);

runtime diagnostic model
  CP++ has two runtime-oriented compilation targets. --run emits checked C++
  for readable CP++ runtime diagnostics and catches those errors in generated
  main. --submit emits lean C++ for submission and does not add readable
  runtime-error checks. Both modes otherwise lower the same CP++ program.

  Example:
    int total=18;
    int zero=0;
    int x=total/zero;

  Diagnostic:
    error: runtime error: division by zero

division by zero
  In --run mode, integer division by zero is checked and reported as a readable
  CP++ runtime error. In --submit mode, division is emitted as ordinary C++.

  Example:
    int numerator=12;
    int denominator=0;
    int answer=numerator/denominator;

  Diagnostic:
    error: runtime error: division by zero

modulo by zero
  In --run mode, integer modulo by zero is checked and reported as a readable
  CP++ runtime error. In --submit mode, modulo is emitted as ordinary C++.

  Example:
    int x = 4 % 0;

  Diagnostic:
    error: runtime error: modulo by zero

integer overflow
  In --run mode, integer +, -, *, and the LLONG_MIN / -1 and LLONG_MIN % -1
  cases are checked and reported as readable integer overflow diagnostics. In
  --submit mode, arithmetic is emitted as ordinary C++.

  Example:
    int x = 9223372036854775807;
    x = x + 1;

  Diagnostic:
    error: runtime error: integer overflow

Whitespace-insensitive parsing
------------------------------

lexer whitespace
  The lexer skips whitespace and does not emit whitespace tokens. Parser
  decisions should be made from tokens, not from the amount of space between
  tokens.

  Example:
    int x
    =8
    ;
    int y=2;
    int z=(x+y)*3/2%7;
    print(z);

for-header semicolons
  Semicolons inside for(...) headers are part of the header, not statement
  separators. This works even when the header has no spaces.

  Example:
    for(int i=0;i<3;i++){
    print(i);
    }

block brace whitespace
  Control-flow opening braces may appear on the same line as the header or on
  their own line. Empty blocks such as if(true){} are accepted.

  Example:
    if(true){}
    while(n<2)
    {
    n++;
    }

empty condition
  Flexible block brace placement does not make an empty condition valid.

  Example:
    if()
    {
    print(1);
    }

  Diagnostic:
    error: expected condition

Multiple statements per line
----------------------------

semicolon-separated statements
  Multiple semicolon-terminated statements may appear on the same physical
  source line and are lowered as separate C++ statements.

  Example:
    int a = 0; int b = 1; print(a,b);

Absolute value
---------------------------------

Absolute value must take in numeric values:

Example:
  int y = abs('o');

Diagnostic:
  error: abs() expects a Numeric value

Sets and Maps
-------------

Set expects 1 subtype like Set<int>
  Set is a generic collection type with exactly one element subtype.

  Example:
    Set values;

  Diagnostic:
    error: Set expects 1 subtype like Set<int>

Set expects 1 subtype
  Set does not accept extra subtype parameters.

  Example:
    Set<int, int> values;

  Diagnostic:
    error: Set expects 1 subtype

unclosed generic type for Set
  Generic Set syntax must close all angle brackets.

  Example:
    Set<List<int> values;

  Diagnostic:
    error: unclosed generic type for Set

cannot add string to Set<int>
  Set.add(value) requires a value compatible with the Set element type.

  Example:
    Set<int> values;
    values.add("hello");

  Diagnostic:
    error: cannot add string to Set<int>

cannot remove string from Set<int>
  Set.remove(value) requires a value compatible with the Set element type.

  Example:
    Set<int> values;
    print(values.remove("hello"));

  Diagnostic:
    error: cannot remove string from Set<int>

cannot check membership of string in Set<int>
  The left side of `in` must match the Set element type.

  Example:
    Set<int> values;
    print("hello" in values);

  Diagnostic:
    error: cannot check membership of string in Set<int>

Map expects 2 subtypes like Map<int, int>
  Map is a generic collection type with exactly two subtypes: key and value.

  Example:
    Map<int> values;

  Diagnostic:
    error: Map expects 2 subtypes like Map<int, int>

Map expects 2 subtypes
  Map does not accept more than two subtype parameters.

  Example:
    Map<int, int, int> values;

  Diagnostic:
    error: Map expects 2 subtypes

add() can only be used on List or Set values
  Map values do not support add(...).

  Example:
    Map<int, int> values;
    values.add(1);

  Diagnostic:
    error: add() can only be used on List or Set values

cannot remove string from Map<int, int>
  Map.remove(key) requires a key compatible with the Map key type.

  Example:
    Map<int, int> values;
    print(values.remove("hello"));

  Diagnostic:
    error: cannot remove string from Map<int, int>

cannot use key of type string with Map<int, int>
  Map.at(key) requires a key compatible with the Map key type.

  Example:
    Map<int, int> values;
    print(values.at("hello"));

  Diagnostic:
    error: cannot use key of type string with Map<int, int>

map key type must be int
  Bracket indexing on a Map must use the Map key type.

  Example:
    Map<int, int> values;
    values["hello"] = 3;

  Diagnostic:
    error: map key type must be int

nested map key type must be int
  Nested Map expressions enforce the key type at every indexing step.

  Example:
    Map<int, Map<int, int>> values;
    print(values["hello"][1]);

  Diagnostic:
    error: map key type must be int

Set, Map, and Pair literals
---------------------------

unclosed brace in set or map literal
  Set and Map literals must close their outer braces.

  Example:
    Set<int> values = {1, 2;

  Diagnostic:
    error: unclosed brace in set or map literal

cannot implicitly convert string to int in set literal
  Set literals report the first element whose type does not match the rest of
  the literal.

  Example:
    Set<int> values = {1, "oops"};

  Diagnostic:
    error: cannot implicitly convert string to int in set literal

Set values must use a set literal like {1, 2} or another Set expression
  Set literals use braces, not square brackets.

  Example:
    Set<int> values = [1, 2];

  Diagnostic:
    error: Set values must use a set literal like {1, 2} or another Set expression

cannot implicitly convert string to int in map literal key
  Map literals report which key fails the declared key type.

  Example:
    Map<int, int> values = {1:2, "oops":3};

  Diagnostic:
    error: cannot implicitly convert string to int in map literal key

cannot implicitly convert int to Set<int> in map literal value
  Map literals also report mismatched value types precisely.

  Example:
    Map<int, Set<int>> values = {1:{2}, 3:4};

  Diagnostic:
    error: cannot implicitly convert int to Set<int> in map literal value

Map values must use a map literal like {1:'a'} or another Map expression
  Map literals use braces, not square brackets.

  Example:
    Map<int, int> values = [1, 2];

  Diagnostic:
    error: Map values must use a map literal like {1:'a'} or another Map expression

print delim requires a List value
  Maps print organically, but delimiter-based printing is reserved for List and
  Set values because a Map already has entry punctuation.

  Example:
    Map<int, int> values = {1:2};
    print(values, delim = ",");

  Diagnostic:
    error: print delim requires a List value

Pair expects 2 subtypes like Pair<int, int>
  Pair is a generic container type with exactly two subtypes.

  Example:
    Pair<int> point;

  Diagnostic:
    error: Pair expects 2 subtypes like Pair<int, int>

Pair expects 2 subtypes
  Pair does not accept more than two subtype parameters.

  Example:
    Pair<int, int, int> point;

  Diagnostic:
    error: Pair expects 2 subtypes

unclosed generic type for Pair
  Nested Pair syntax must close all angle brackets.

  Example:
    Pair<int, Pair<int, int> point;

  Diagnostic:
    error: unclosed generic type for Pair

unsupported type Pair<void, int>
  Pair subtypes must themselves be valid CP++ value types.

  Example:
    Pair<void, int> point;

  Diagnostic:
    error: unsupported type Pair<void, int>

cannot implicitly convert string to int
  Pair elements only swap directly when each side can be assigned to the other.

  Example:
    Pair<int, string> point = (7,"x");
    point[0], point[1] = point[1], point[0];

  Diagnostic:
    error: cannot implicitly convert string to int

pair index must be 0 or 1
  Pairs only expose two positions: [0] and [1].

  Example:
    Pair<int, int> point = (1,2);
    print(point[2]);

  Diagnostic:
    error: pair index must be 0 or 1

Ordered collection helpers
--------------------------

cannot use key of type string with Set<int>
  Set.prev(...) and Set.next(...) require a value compatible with the Set
  element type.

  Example:
    Set<int> values = {1, 2};
    print(values.prev("x"));

  Diagnostic:
    error: cannot use key of type string with Set<int>

cannot use key of type string with Map<int, int>
  Map.prev(...) and Map.next(...) require a key compatible with the Map key
  type.

  Example:
    Map<int, int> values = {1:2};
    print(values.next("x"));

  Diagnostic:
    error: cannot use key of type string with Map<int, int>

unclosed parenthesis in prev
  Ordered helper calls must close their argument list.

  Example:
    Set<int> values = {1, 2};
    print(values.prev(1);

  Diagnostic:
    error: unclosed parenthesis in prev

cannot check membership of Pair<int, Set<int>> in Map<Pair<int, Set<char>>, int>
  Map membership checks use the declared key type exactly, including nested
  Pair and Set structure.

  Example:
    Map<Pair<int, Set<char>>, int> values;
    print((1,{1}) in values);

  Diagnostic:
    error: cannot check membership of Pair<int, Set<int>> in Map<Pair<int, Set<char>>, int>

cannot take max of empty set
  In --run mode, max(set) reports a readable runtime error when the Set is
  empty.

  Example:
    Set<int> values;
    print(max(values));

  Diagnostic:
    error: runtime error: cannot take max of empty set

no next value in set
  In both --run and --submit mode, Set.next(x) reports a readable CP++
  runtime error when there is no larger value.

  Example:
    Set<int> values = {2, 5, 9};
    print(values.next(max(values)));

  Diagnostic:
    error: runtime error: no next value in set

no previous key in map
  In both --run and --submit mode, Map.prev(x) reports a readable CP++
  runtime error when there is no smaller key.

  Example:
    Map<int, int> values = {2:7, 5:1};
    print(values.prev(1));

  Diagnostic:
    error: runtime error: no previous key in map

Type inference errors
---------------------

var declarations require an initializer so the type can be inferred
  `var` must be initialized immediately because its declared type comes from
  the right-hand expression.

  Example:
    var x;

  Diagnostic:
    error: var declarations require an initializer so the type can be inferred

var cannot be initialized with input(); declare the type explicitly
  Raw `input()` does not carry enough type information for `var`.

  Example:
    var x = input();

  Diagnostic:
    error: var cannot be initialized with input(); declare the type explicitly

var cannot infer a type from an empty container; declare the type explicitly
  Empty containers like `[]` and `{}` need a declared destination type.

  Example:
    var values = [];

  Diagnostic:
    error: var cannot infer a type from an empty container; declare the type explicitly

var declarations support exactly one variable
  `var` keeps inference local to one variable at a time.

  Example:
    var a, b = 1, 2;

  Diagnostic:
    error: var declarations support exactly one variable

var declarations must use '=' with an initializer
  `var` is only valid for initialized declarations.

  Example:
    var x 3;

  Diagnostic:
    error: var declarations must use '=' with an initializer

cannot implicitly convert string to int
  Inferred `var` bindings still keep one concrete type after declaration.

  Example:
    var x = 1;
    x = "hi";

  Diagnostic:
    error: cannot implicitly convert string to int

invalid variables suppress cascaded errors
  Once a declaration has already failed, later uses of that variable do not
  produce extra follow-on diagnostics in the same compile pass.

  Example:
    var x = input();
    x += 1;
    if (x < 5) {
        x *= 2;
    }
    int y = "ass";

  Diagnostic:
    error: var cannot be initialized with input(); declare the type explicitly
    error: int requires an integer literal
